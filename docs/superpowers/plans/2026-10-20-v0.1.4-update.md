# 0.1.4 下一步更新计划

记录日期：2026-10-19。用户要求先记录，后续实施；本文件不代表功能已实现或0.1.4已发布。

## 版本安排

- 当前已发布：0.1.3-C1BE-10FF-C10D，versionCode=1009。
- 用户明确指定下一版基础版本：**0.1.4**，覆盖此前“小改动统一留在0.1.3”的规则，限于下一批正式升级。
- 实际交付时设置versionName=0.1.4，保留三个四位大写十六进制随机索引；versionCode须大于1009，若期间无其它发包使用1010。
- 开始发包时再登记新索引、修改app/version.properties并构建到dist/0.1.4；不重命名旧APK、不将历史误标0.1.4当作此次发布。

## P0：搜刮一键放入背包（新增）

用户原意按“一键放入，不必过度智能”记录。

- [ ] 掉落区添加明确按钮“**一键放入背包**”。
- [ ] 只处理已经鉴定完成、仍在地面的物品；未鉴定物品保持等待，不跳过动画。
- [ ] 按当前掉落列表顺序逐件尝试，扫描背包上到下、左到右的空位；复用现有90°旋转校验。
- [ ] 放不下的留在原掉落区，继续尝试后面物品；不移动/压缩已在背包里的物品，不按价格做取舍。
- [ ] 不自动装备、不放入技能栏、不自动塞安全箱、不丢弃物品；手动拖放仍可用。
- [ ] 保留拾取实例、星级、绑定、数量，复用NodeLootRules.collect，保存成功才显示获得。
- [ ] 给出简短结果：“已放入N件，剩余M件”；空间不足与仍待鉴定能区分。
- [ ] 全部取完且鉴定完成时，沿用现有自动返回远征并结束掉落节点；下一战仍先整备。
- [ ] 批次事务复核：失败不产生重复物品、超容量或假成功；连点、切后台、重进节点不重复拾取。
