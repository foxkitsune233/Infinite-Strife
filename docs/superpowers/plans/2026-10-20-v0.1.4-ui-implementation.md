# 0.1.4 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the first coherent portrait UI for expedition, loadout, and loot collection while retaining the current game rules and save format.

**Architecture:** Activities remain owners of repository transactions and game state. Reusable view primitives own only drawing, hierarchy, selection and drag feedback; all business operations continue to call `InventoryRules`, `NodeLootRules`, and `JourneyRules` through their existing Activity callbacks. The visual system is the teal-stone / gold-compass language shown in the approved storyboard.

**Tech Stack:** Kotlin, Android Views, existing `GameUi`, `CutPanelDrawable`, `InventoryBoardView`, shared Kotlin game rules.

## Global Constraints

- Next release name is `0.1.4-XXXX-XXXX-XXXX`; versionCode is greater than 1009 when packaging begins.
- Keep all rules, save transactions and economic formulas outside UI components.
- User runs acceptance tests externally; local work compiles Android and shared JS and creates a test table.
- Portrait first; 320dp and text scale 1.3 must not hide primary actions.
- No automatic item loss, safe-box transfer, equipment swap, or undisclosed appraisal shortcuts.

## External Work Reserved for User

- `LootPickupBatch`: atomic, idempotent one-tap pickup rule using only revealed ground loot; leaves failures on ground; returns picked/remaining counts.
- `HeroStatSnapshot`: shared, real computed values and source contributions for the forthcoming detailed-stat screen.
- Merchant refresh state: return a current shelf/quote after an automatic-cycle stale-price rejection.
- Crafting availability: expose total, unlocked, locked and consumable ingredient counts separately.
- Gameplay and balance work: control-chain sampling, currency tuning, enemy loadouts, reward/drop tables.
- External device tests, emulator installation and release sign-off.
