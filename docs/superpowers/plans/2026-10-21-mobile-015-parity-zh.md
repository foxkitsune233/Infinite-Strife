# Godot 移动端 0.1.5 核心闭环迁移计划（中文对照）

> **历史原型记录。** 从 2026-10-21 起，功能范围以 [Android 0.1.5 功能复刻基线](../specs/2026-10-21-android-parity-design.md) 和 [复刻执行计划](2026-10-21-android-parity-rebuild.md) 为准。后续实现采用 Android 的 9 装备位、8 技能卡位、三套方案和完整远征流程；本文中的原创 6/6 范围不再作为验收依据。

对应英文原版：[2026-10-21-mobile-015-parity.md](2026-10-21-mobile-015-parity.md)

## 目标与边界

目标不是复制 Android 版的角色、美术或原始内容，而是制作一个**原创、竖屏、触摸优先**的 Godot 版本，达到 Android 0.1.5 的核心可玩闭环：

`选英雄与构筑 → 五节点远征 → 战斗 → 拾取与鉴定 → 背包/合成/商店 → 保存并继续`

| 约束 | 约定 |
| --- | --- |
| 主平台 | 手机竖屏，逻辑画布 `720×1280` |
| Windows | 仅用于模拟手机画布、调试与导出验证 |
| 原创边界 | 不复用 Android 的第三方角色、美术、名称、轮廓、音频、数值表或运行时代码 |
| 可复现性 | 相同种子和相同操作必须产生相同的战斗与远征日志 |
| Android 原版 | 独立维护，不被 Godot 改动影响 |
| 网页/iOS | 不阻塞此迁移；分别在 Godot Android 核心完成和具备合规 Apple 环境后再处理 |

## T1：竖屏应用壳与移动导航

**已完成内容**

- 主逻辑画布从横屏 `1280×720` 改为竖屏 `720×1280`。
- Windows 调试窗口也采用竖屏比例，避免把桌面横屏布局误当成手机完成度。
- 战斗页双方由左右排列改为上下排列。
- 添加 `ScreenRouter`，目前注册主页和战斗页；无效页面 ID 返回空路径并拒绝切换。

- `scenes/MainMenu.tscn`
- `scenes/Battle.tscn`

## 后续实施顺序

### T3：先完成战斗规则与战斗表现基础层

**当前进度**：已完成护甲、护盾、蓝量、魔抗、技能冷却、眩晕、沉默、暴击、吸血、DOT、加速/减速、主动装备命令、结构化战斗日志与特效 ID 映射。已接入一张竖屏战场背景和两名原创角色的待机立绘，并登记来源。待补的是实际特效节点播放、更多角色动作与设备端触摸验收。

1. Fighter 增加 HP、MP、护盾、控制状态、冷却和主动装备状态。
2. 战斗引擎增加物理/魔法伤害、护盾优先吸收、法力不足、CD 拒绝、眩晕和沉默。
3. 每个动作输出结构化日志，UI 只读取快照和日志。
4. 使用固定种子测试：护甲、护盾、击杀、超时、控制、主动装备与技能。
5. 引入原创、可公开分发的基础战斗资源：英雄战斗立绘、敌人立绘、竖屏战场背景、技能特效、状态图标与受击数字样式；资源逐项登记来源和许可证。
6. 为每个角色定义统一的脚底、武器与特效锚点。首轮只要求待机、受击、普攻和施法四类表现可正确播放；高规格逐帧连招与角色专属演出作为后续美术迭代。

**完成后玩家能看到：** 两个原创英雄带有正式的基础战斗形象，在竖屏战斗中自动攻击、释放技能、消耗蓝量、进入冷却，并明确显示生命、蓝量、护盾和状态。

**T3 资源清单与验收**

| 类别 | 第一轮接入范围 | 验收要求 |
| --- | --- | --- |
| 英雄战斗图 | 2 名可玩英雄：待机、普攻、受击、施法 | 竖屏战场中不裁切，脚底与武器锚点稳定 |
| 敌人战斗图 | 2 种敌方单位：待机、普攻、受击 | 能和玩家单位使用同一套距离与受击规则 |
| 场景 | 1 张原创青绿遗迹战场背景 | 适配 `720×1280`，不影响状态面板阅读 |
| 技能特效 | 物理斩击、魔法弹、护盾、治疗、控制各 1 套 | 能由结构化战斗日志正确触发与结束 |
| 状态图标 | 护盾、眩晕、沉默、减速、DOT、暴击、冷却 | 图标、持续时间和实际状态一致 |
| 音效占位 | 普攻、命中、技能、护盾、击杀 | 使用原创或明确可商用来源；没有正式音频时可安全静音 |

### T4：再接入整备与构筑

1. 英雄选择和已保存配装切换。
2. 上部压缩为英雄信息、六装备槽、六卡槽。
3. 下部为可筛选物品/卡牌库；点按放置，长按拖动。
4. 替换时退回旧物品；显示流派层数和实际收益。

**完成后玩家能做到：** 换英雄、选择六件装备与六张卡，并在出发前理解构筑收益。

### T5：远征、事件和掉落

1. 一局生成五个节点，包含战斗与事件。
2. 六档难度按敌方预算、成长、信息透明度和掉落来源递进。
3. 战后物品落在掉落区，玩家手动放入背包；没带走时点击“返回远征”确认丢弃。
4. 物品按尺寸、品质与价值播放不可跳过的鉴定时间；第五战目标宝箱直入营地仓库。

### T6：背包、合成和商店

1. 真实尺寸网格、旋转、占位高亮、替换与失败提示。
2. 一键整理、批量放入、快速出售与锁定。
3. 合成界面先显示可合成项目，不可合成项目置后并加暗遮罩。
4. 商店支持刷新版本号；使用旧价格购买会拒绝并返回新货架。

### T7：存档与发布验收

1. 存档保存当前英雄、配装、背包、营地、远征节点和待鉴定掉落。
2. 旧存档补默认字段；未来版本不会覆盖存档。
3. 主页提供“继续远征 / 新远征 / 整备 / 设置”。
4. Windows 与 Android 产物各自执行竖屏触摸、暂停恢复、存档恢复与完整一局验收。
