# 主题宝箱与材料保底接入 Implementation Plan

**Goal:** 从普通随机材料池推进到六主题、多维箱列表与按材料类别隐藏保底。
**Architecture:** shared的ChestFactory负责一次生成/单箱替换，MaterialProgression负责成长需求与07保底资格映射；JourneyRules仅调用生成和一次终局记录。v6显式保存箱主题/保底来源与类别计数，兼容v1～v5，不改20～22独占测试。
**Tech Stack:** Kotlin MPP/JVM/JS与既有Android UI/二进制存档；不新增依赖。

- [x] 六主题、4/6/8批次、保留低价入口、单箱刷新不改主题/难度，救济只补综合低成本箱。
- [x] 复用07按背包/技能4次、安全箱6次计数，只有已开放且仍有需求的对应主题通关未带出才累计。
- [x] 生成即消耗且一次资格仅一箱；普通生成/单箱刷新/救济均走同一生成入口，不为未展示的箱子浪费保底。
- [x] 新获材料通过目标箱/途中/安全箱成功带出则重置；仓库旧材料不重置；失败/撤离不增加miss；终局不可重复记录。
- [x] v6追加字段，读取旧箱默认综合补给、空计数；旧箱内容/价格/鉴定保持，20～22原API兼容。
- [x] UI显示真实主题与难度，不暴露隐藏保底；编译与只读复核；外部23/24测试表，不自动执行测试/模拟器。

首轮权重是实现参数而非平衡结论。工程主题偏向各自材料，所有主题仍可有混合物资；保底只作用专用材料。背包与技能材料保底最低难度0、安全箱最低难度1；资格还需满足当前成长进度。后续可配置化调整。
