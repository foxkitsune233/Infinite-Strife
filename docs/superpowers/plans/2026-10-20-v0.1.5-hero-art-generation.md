# 0.1.5 新英雄美术资产生成 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为四名 0.1.5 新英雄生成统一风格的透明待机、攻击关键帧、头像和可供卡面生产使用的视觉参考，并保存为项目内可审阅资产。

**Architecture:** 先生成每名英雄一张包含待机与攻击动作分镜的审阅稿，人物、武器、脚底与动作轨迹在同一张图中锁定。用户确认姿势后，才导出透明待机、四帧图集和头像；运行时配置只在最终素材通过审阅后修改。

**Tech Stack:** built-in image generation、透明 PNG、现有 Android assets、`hero-animation-manifest.json` 与 `attack-atlas-v3.json`。

## Global Constraints

- 画风：高饱和度 2D 卡通、粗黑描边、Dota 气质，人物可读性优先。
- 人物不得带文字、水印、UI、伤害数字、背景特效或技能光效。
- 角色统一右朝向，512 × 512 单帧，脚底根点目标 `(256, 464)`；左朝向由运行时镜像。
- 攻击统一四帧：`ready → windup → strike → recovery`。
- 敌法师为女性，使用双月刃与反魔战士造型，不复用 PA 的刺客剪影。
- 不覆盖已有六英雄素材；所有新增图先使用 `-v1` 文件名。
- 当前目录不是 Git 工作树；不执行 `git commit`、建库或推送。

- [ ] **Step 1: 为敌法师生成审阅稿**

  生成一张透明背景的女性敌法师动作板：五个右朝向全身姿势等距排开，双月刃尺寸一致，脚底基线一致；紫蓝轻甲、浅金护甲边、反魔符文，绝不出现 PA 式面罩或匕首。

- [ ] **Step 2: 为斧王生成审阅稿**

  生成一张透明背景的斧王动作板：五个右朝向全身姿势等距排开，巨斧在蓄力到命中间连续横扫；红铜重甲、暗灰皮革、宽肩、低重心。

- [ ] **Step 3: 为虚空假面生成审阅稿**

  生成一张透明背景的虚空假面动作板：五个右朝向全身姿势等距排开，单手钉头锤从回撤、蓄力到下砸保持连续；靛紫皮甲与少量青蓝裂纹。

- [ ] **Step 4: 为军团指挥官生成审阅稿**

  生成一张透明背景的军团指挥官动作板：五个右朝向全身姿势等距排开，长剑从腰侧收剑、前冲、刺击到回守连续；红金军团甲、深红短披风、军官姿态。

- [ ] **Step 5: 视觉验收与用户审阅**

  对每张稿检查：五个姿势完整、武器没有穿手／断裂、脚底共线、右朝向一致、人物之间配色不混淆、没有文字或背景。将四张图和审阅记录交给用户，等待逐名批准或提出修改。

- [ ] **Step 1: 生成一名已批准英雄的待机、图集和头像**

  基于同一动作稿生成透明待机 PNG、四张 512×512 连续关键帧组成的 512×2048 纵向图集、以及以头肩为主体的方形头像。先检查文件尺寸和透明背景，再处理下一名英雄。

- [ ] **Step 2: 逐名重复并做锚点校验**

  对四名英雄分别检查四帧脚底均落于同一 `y=464` 基线、武器握点连续、命中帧没有裁切、头像和待机角色一致。

- [ ] **Step 3: 写入动作元数据**

  在 `attack-atlas-v3.json` 新增四个 hero ID 的 `file`、`frameWidth`、`frameHeight`、`rootX`、`rootY`、`bodyHeight`、`contentWidth`、`attackOriginX`、`attackOriginY` 和武器握点；在 manifest 增加 `idle`、`attack`、`attackKind`、`hitAtMs`。不得更改已有六英雄字段。

- [ ] **Step 4: 设备视觉验收**

  在战斗场景检查右侧人物、左侧镜像人物、高攻速连续攻击、头像缩略图、武器不穿手、脚底不漂移。记录截图和问题；任何姿势问题只重生成该英雄，不改其他英雄。

### Task 3: 新流派卡面前置设计

**Files:**
- Create: `docs/design/2026-10-20-v0.1.5-school-card-brief.md`

**Consumes:** 四名英雄的已批准人物语言；后续用户确认的四流派机制、命名、羁绊与卡表。

**Produces:** 每流派的主色、象征物、构图、角色专属卡露出规则和每张卡的插画提示词；不生成卡图。

- [ ] **Step 1: 确认四流派内容设计**

  逐一确定四个流派的机制名称、羁绊 2/3/4 档、每张卡的触发和数值范围。未确认的流派不进入卡图生成。

- [ ] **Step 2: 输出卡面简报并审阅**

  每张卡定义一个唯一视觉主体、主色和负面约束；通用卡不复用英雄立绘，双流派卡明确两种视觉元素的交汇方式。用户确认简报后才进入批量卡图生成。
