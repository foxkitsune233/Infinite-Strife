# Godot Android 0.1.5 功能复刻基线

## 目标

Godot 版本以当前 Android 0.1.5 的玩家流程、数据规模和操作语义为基线重建，而不是另做一套简化玩法：

`主页 → 整备 → 五节点远征 → 战斗／事件 → 掉落与鉴定 → 返回整备`

所有运行时逻辑以 GDScript 重写；Android 项目只作为行为、数据和验收参考。

## 美术与来源

- 优先复用 Android 工程中已确认由项目组重绘或原创的资源。
- 每份复用资源在 `assets/ASSET_REGISTER.md` 记录来源、作者确认和用途。
- 来源不明的遗留资源不进入 Godot 的发布路径，先以占位资源替代。
- 本阶段不补绘新角色或卡图；先保证既有视觉资源能在竖屏流程中正确承载功能。

## 与 Android 的关键对齐

| 能力 | Android 约束 | Godot 复刻规则 |
| --- | --- | --- |
| 整备配装 | 9 装备位、8 技能卡位、3 套方案 | 完全保留位数、方案数和替换语义 |
| 英雄切换 | 自动加载该英雄最近选中的方案 | 无有效方案时保持当前空位，不伪造物品 |
| 方案保存 | 仅营地可保存；存实例 ID 和手动状态 | 离开营地时拒绝保存，并给出可显示原因 |
| 替换 | 拖到占用格时旧物回仓库 | 新旧实例原子交换，不重复、不丢失 |
| 仓库 | 真实物品尺寸、旋转、锁定、整理、快速出售 | 使用同一网格尺寸和容器规则，不以列表替代 |
| 远征 | 5 节点、战斗/事件/掉落/鉴定/目标宝箱 | 节点状态、掉落归属和离开丢弃规则可存档 |
| 战斗 | 蓝量、护盾、状态、CD、主动装备、60 秒结算 | 继续以确定性日志驱动表现，补齐 Android 规则 |
| 存档 | 版本迁移、未来版本安全拒绝 | 保存整备、远征和待鉴定状态，绝不覆盖未来存档 |

## 页面结构

1. **主页**：继续远征、新远征、整备、设置、版本日志。
2. **整备一级页**：上半部为英雄头像、9 装备位、8 卡位、3 套方案；下半部为仓库入口和主要操作。
3. **整备二级页**：仓库、合成、商店、物品/卡牌详情等内容在独立页面或抽屉中显示，避免一级页堆叠全部文本。
4. **远征页**：明确展示当前节点、敌人预览、主动装备信息和“进入战斗”。
5. **战斗页**：沿用竖屏 Android 信息层级；事件、掉落、鉴定均使用独立阶段而非内嵌小面板。

## 实施顺序

1. P1：配装领域模型、英雄方案、9/8 位替换与仓库回收。
2. P2：竖屏整备页和二级仓库入口，接入 P1 状态。
3. P3：网格库存、物品实例、旋转、锁定、整理、快速出售。
4. P4：合成、商店与敌方主动装备预览。
5. P5：五节点远征、事件、手动拾取、鉴定和目标宝箱。
6. P6：补齐战斗规则与 Android 对照测试，接入英雄、卡牌、装备内容。
7. P7：版本存档、版本日志、Android/Windows 导出与设备验收。

## 首个验收单元：P1

- 配装有且仅有 9 个装备位、8 个卡位和 3 套方案。
- 保存方案保存实例 ID；同一实例不能同时保存到多个槽位。
- 拖到已占用槽位时，新物进入目标、旧物返回仓库。
- 切换英雄自动应用该英雄最后选择的有效方案；缺失实例从方案中清除，不中断操作。
- 仅营地状态允许保存方案。
