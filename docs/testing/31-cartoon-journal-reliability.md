## 日志与战斗异常

入口：设置→存档与诊断→导出完整战斗记录ZIP；同页可查看最近异常。

| ID | 操作 | 期望 |
|---|---|---|
| L01 | 完整进行一战后导出ZIP | frames/*.jsonl含battle_start、各tick前后状态、RNG、双方HP/MP/盾、控制、装备CD、卡/毒原始快照和语义事件；附current-profile.dqq及说明 |
| L02 | 手动装备、恢复品、切换自动/手动及失败操作 | 日志中有物品实例ID、模式或拒绝原因；同tick操作通过session/sequence排序；不额外推进随机数 |
| L03 | 打盾暴击、普通毒、剧毒产层、驱散、治疗、BKB | 前后状态和实际伤害事件一致；剧毒产层不是伤害；所有来源细分尚不属于稳定结构化事件API，可从rawFighter辅助分析 |
| L04 | 循环丢回调、计算异常、写盘失败、慢磁盘 | 回调超时在前台尝试从已存帧恢复；计算/存档失败保留原档并停止；导出last-diagnostic含run/round/tick及异常；不是无限自动重试 |
| L05 | 后台/强杀/恢复、跨战 | 停留后台不推进战斗；恢复不会重抽；新进程有新session，各场runId/round可关联。排队尚未落盘的尾部日志允许丢失，存档仍为权威 |
| L06 | 写队列压力与长期多局 | 记录缺失用droppedBefore/序列缺口/README未报告计数显式提示；约48MiB轮替保留，不承诺无限历史；日志失败不阻断战斗 |
| L07 | 复现“约7秒停住” | 记录停顿前后场号、tick、切页/后台步骤并导出ZIP；本轮只做诊断与回调恢复，未宣称已找到根因 |
| L08 | 装备推推/长戟后施加控制 | 保护计时真正上升才出现短后撤、环形光与推力线；不改变战斗距离/伤害规则，读档已有保护不重播启动动画 |

## 鉴定收据

| ID | 中断/操作 | 期望 |
|---|---|---|
| R01 | 正常付费鉴定、后台恢复、自动商店刷新 | 同一收据恢复剩余进度；不重复扣费。自动恢复次数/换货不应令合法收据失效 |
| R02 | 第五战通关后后台/强杀 | 发奖只一次；演出绑定结算后业务快照，重新生成下一批箱不破坏合法收据 |
| R03 | 准备收据后、业务存档提交前中断或保存失败 | 存档仍为旧业务状态；不收费不发奖，未提交收据被隔离留证，不展示无关箱 |
| R04 | 业务存档提交后、演出窗口出现前中断 | 预先准备的收据与新状态匹配，重启后强制继续演出，不靠事后enqueue补救 |
| R05 | 恢复另一份备份或旧箱ID碰撞但内容不同 | 业务指纹或宝箱内容token不匹配，隔离旧收据，金币/物品不改；导出inspection-receipt.json可查看隔离内容 |
| R06 | 老版无owner收据 | 只有唯一当前鉴定箱线索匹配，或唯一完整通关发奖实例组匹配，才绑定迁移；无法证明归属则隔离原记录并告知，不伪称已核验 |
| R07 | 收据JSON损坏、未知物品、非法揭示度 | 坏记录隔离保留，不把应用锁死在无法恢复的弹窗；不绕过合法归属已确认的待完成收据 |
