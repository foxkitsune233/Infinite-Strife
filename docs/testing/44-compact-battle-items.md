# 44号：单排图标战斗装备栏

用户指定的交互：移除装备名、立即使用、冷却文字与自动/手动标签；6个槽放一排，大幅压缩底部高度。

## 显示与操作

- 正常可用：黄色边缘与柔光；长按切换自动/手动。
- 冷却：深色扇形遮罩从12点位置开始顺时针消退，以真实剩余游戏时间/完整CD计算，不靠墙钟假减CD。
- 自动：沿八角按钮边缘顺时针移动的高亮；即使冷却也保留自动模式提示。关闭动画时停止流动，保留静态亮段与顶部金色标记。
- 手动：没有流动边缘；可用金边仍保留。点击立即走原真实物品事务。
- 被控制、冷却或被动装备：不显示可用金光；点击查看详情。长按切模式不因CD或眩晕而被禁用；被动装备长按仅详情。
- 消耗品叠数保留右下角数字，数量耗尽后变为空槽；不恢复数量。
- 无障碍读出物品名、可用/冷却/受限、模式；辅助操作有“查看物品详情”。长按不同时触发使用，模式存档与JSONL保持原规则。

布局：单排6槽，行高60dp，外层上下各4dp，普通320dp宽设备每槽可保持至少48dp点击区；更窄的分屏尺寸需外部检查。实际图标按槽宽/高度居中，沿用独立彩绘。

原先依靠界面文本定位的脚本需改用图标的contentDescription（以物品名称开头），模式改为长按目标图标。冷却中控件仍可交互，不能用enabled=false判断是否可释放，应读取无障碍说明或真实事务结果。

### 过程中记录的非缺陷现象

- **journal 的 `player.manualItems` 是战斗起始快照值**：mode 事务记录写入时的 fight 快照尚未同步；下一 tick 才用 `progress.manualItems` 同步（`JourneyRules.tick`）。U06 以单步 tick 后的同步值为准，非缺陷。
- **`equipmentCooldowns` 键是冷却组**（如 `bkb`）而非装备 ID；耗尽后键消失（视作 0）。
- **运行中 `uiautomator dump` 取不到 idle 快照**：C02 等不暂停场景先点固定坐标 (200,630) 冻结再 dump；单步/继续/暂停按钮坐标固定 (539/879/200, 630)。
- **C11 预设全手动；若曾被切自动并“继续”，引擎会立刻自动触发**（BKB 驱散沉默、臂章/笛子/赤红甲连发）——这是自动模式生效的铁证，不是误触。
- 沙箱内 python 子进程 adb pull 偶发截断/丢失：截图统一由脚本 screencap + Bash 工具 pull 落盘。
- 模拟器长时间驱动后会系统性卡顿（uiautomator dump 60s 超时、任务被关）：重启 Pixel36（`-no-snapshot-load`）后恢复；AVD 目录为 `Pixel36.avd`。
- TalkBack 首次启用会弹通知权限对话框：`pm grant com.google.android.marvin.talkback android.permission.POST_NOTIFICATIONS` 后不再弹。
