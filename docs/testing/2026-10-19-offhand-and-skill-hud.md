# 交替攻击与技能 HUD 外部验收

本轮不执行 Gradle、JUnit 或模拟器；设备测试由外部完成。

## 交替攻击

- 主宰、PA：连续观察两次完整普攻，首次沿用原主手，第二次使用另一只手的新增蓄力/出手，再回到收招。双手不能只是整个角色镜像。对手整人翻转面向左属于正常朝向处理。
- 检查原帧与副手帧切换时脚底不跳、人物体型不跳、武器不裁切；高速普攻不会每次命中都中断正在播放的完整挥击。
- 关闭动画时仍使用稳定待机；两种挥击只影响展示，不改变命中、伤害、攻击频率、技能判定。
- 可先查看 `art-source/heroes/attack-v4/offhand-registered-preview.png` 与 `alternating-hands-preview.gif`。

## 技能信息

- 双方 HUD 均显示正确大招名称和 `HeroSpec.manaCost`，持续显示 `Fighter.ultIn` 剩余秒数；冷却为零时显示冷却已就绪。
- 魔法未达到耗蓝量时显示“魔法不足”与向上取整的差额，即使正在冷却也保留此原因；恢复到足够魔法后清除此原因。
- 眩晕、妖术、沉默、放逐、死亡均读取实际当前控制状态；多个原因同时存在时同时列出。疯狂面具激活时按引擎规则显示沉默；亚巴顿可以在眩晕中施放，不应误报为禁止。
- 仅缴械或物品禁用不应阻止英雄大招；有减冷却卡牌或装备时直接显示真实剩余冷却，不重新计算基础冷却。
- 冷却已结束、魔法足够且权限允许时显示“已就绪 · 自动施放”。在窄屏与系统大字体下检查名称/耗蓝/原因文字均可换行读取。

接入点：`BattleSceneView.kt` 的双方 `FighterHud` 内嵌 `HeroSkillHud`，每次 `bind` 直接读取快照；`DuelIllustration.kt` 记录完整可见挥击序号；`AttackAtlas.kt` 读取可选 `alternateFile` 中的 4/5 帧。未修改共享战斗规则。
