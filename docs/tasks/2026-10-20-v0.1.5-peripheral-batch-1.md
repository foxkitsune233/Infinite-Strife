# 0.1.5 外围批次 1：事件模型与稳定结果契约

## 目标

为 0.1.5 的 16 类事件建立可供主任务接入的外围 Kotlin 契约。先完成事件 ID、选项、稳定结果映射、确定性生成和旧档兼容测试；本批不实现新英雄战斗技能、不接入插画位图、不调整经济数值。

## 允许修改的文件

- `shared/src/commonMain/kotlin/com/example/douqiuqiu/event/EventCatalog.kt`
- `shared/src/commonMain/kotlin/com/example/douqiuqiu/journey/JourneyEvents.kt`
- 对应 `commonTest` 或 `app/src/test` 测试文件
- 如需补充纯数据映射，可新增同目录 `EventOutcomeArt.kt`

禁止修改 `JourneyActivity`、战斗引擎、英雄技能、掉落平衡表和图片资源。

## 第一阶段实现内容

### 1. 追加事件枚举与目录定义

新增以下 8 个 `EventKind`，保留原有 8 个值和顺序兼容：

| EventKind | 标题 | 选项 ID |
|---|---|---|
| `FROZEN_SHRINE` | 冰封祭坛 | `attune` / `pray` / `leave` |
| `WAR_BANNER_RUINS` | 战旗遗址 | `claim` / `blood_rite` / `leave` |
| `ROVING_CARAVAN` | 流动商队 | `buy` / `sell` / `depart` |
| `ROPEWAY_BRIDGE` | 断桥索道 | `cross` / `repair` / `leave` |
| `PACT_ALTAR` | 秘契祭坛 | `offer_medicine` / `offer_blood` / `refuse` |
| `ALCHEMY_LAB` | 失控炼金室 | `distill` / `break_seal` / `leave` |
| `HUNTER_CAMP` | 猎人营火 | `barter` / `share_rations` / `leave` |
| `MOONWELL_ECHO` | 月井回响 | `resonate` / `draw_echo` / `leave` |

每个选项必须声明风险、条件和交物要求；可能致死的选项文案必须包含“可能死亡”。

### 2. 稳定结果映射

每个事件的 3 个结局使用唯一 `outcomeId` 与 `artKey`：

```text
<event-kind>.<option-id>
```

例如：`frozen_shrine.attune`。结果页不得根据标题、列表序号或随机数重新推导图片 key。

### 3. 确定性生成

- 同一 `seed + nodeId + kind` 必须得到相同 `roll`、价格、需求物和选项集合。
- 最近两个节点不重复同类事件；候选不足时只放宽为排除最近一个。
- 生成结果写入 `NodeEventInstance` 后，重进节点不能重新生成。
- 失败结算必须返回原状态，不能消费金币、物品或生命。

### 4. 旧档兼容

- 旧 8 类事件的枚举名、二进制顺序和既有 option ID 不变。
- 旧档没有结果图字段时读为空，调用方回退到事件入口图。
- 不改变已有 v9 存档块的读取顺序；若新增字段，必须走版本追加或等价兼容路径。

## 最低验收用例

| ID | 断言 |
|---|---|
| EV01 | 16 个事件 kind 唯一；新增 24 个 option/outcome/art key 全部非空且无重复 |
| EV02 | 同 seed/node 连续生成 100 次完全一致 |
| EV03 | 事件读档、重进后价格、交物要求、奖励和 art key 不变 |
| EV04 | 最近两次不重复；候选不足时只放宽到最近一次 |
| EV05 | 金币不足、空间不足、交物不匹配时状态逐字段不变 |
| EV06 | 月井无达标羁绊时 `resonate` 禁用，达标后启用 |
| EV07 | 旧档缺结果图字段时可读，并回退入口图 |
| EV08 | 交物事件未明确授权时不能消耗安全箱实例 |
