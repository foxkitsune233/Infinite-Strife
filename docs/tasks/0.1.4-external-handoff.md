# 0.1.4 外围任务交接

UI 页面、拖拽表现、图鉴与页面导航由主任务负责。以下任务不改 `ui/` Activity、`GameUi.kt`、`InventoryBoardView.kt`、`InventoryShelfView.kt`，完成后可独立交付。

## X01：搜刮一键放入的原子规则

**负责范围**：`journey/NodeLootRules.kt` 或与其同包的新纯规则文件；需要的 shared 单测。

**接口建议**：

```kotlin
data class BatchLootResult(
    val state: InventoryState,
    val pickedIds: List<String>,
    val remainingIds: List<String>,
    val pendingInspectionIds: List<String>
)

fun collectRevealedIntoBackpack(state: InventoryState): InventoryResult
```

**规则**：

- 仅处理当前节点已鉴定、仍在地面掉落区的实例。
- 按节点掉落的现有顺序逐个尝试；每件从背包左上开始找空位，普通方向失败后尝试旋转90°。
- 不移动已有背包物品，不整理、不自动装备、不进入技能栏或安全箱，不丢弃。
- 一件放不下时留在地面，继续处理下一件；返回已拾取、剩余、待鉴定数量。
- 全部失败、部分成功、连续调用、保存失败重试均不能复制或丢失实例。
- 规则只返回状态；存档由调用方完成。

**验收样例**：可全部放入、仅第二件放不下、仅旋转可放、全部满、混有未鉴定掉落、重复调用不重复拾取、取走最后一件仍由现有 Journey 结束节点。

## X02：英雄详细数值快照

**负责范围**：`shared` 或 `journey` 的只读计算模型；不创建 Android 页面。

**接口建议**：

```kotlin
data class StatValue(
    val total: Double,
    val base: Double? = null,
    val equipment: Double? = null,
    val cards: Double? = null,
    val synergy: Double? = null
)

data class HeroStatSnapshot(
    val hp: StatValue, val mana: StatValue, val attack: StatValue,
    val armor: StatValue, val magicResistance: StatValue,
    val attackSpeed: StatValue, val healthRegen: StatValue,
    val manaRegen: StatValue, val lifesteal: StatValue,
    val cooldownReduction: StatValue, val statusResistance: StatValue
)

fun snapshot(state: InventoryState, heroId: String, battle: Fighter? = null): HeroStatSnapshot
```

**规则**：

- 总值必须与现有英雄/装备/卡牌/羁绊计算一致，不让 UI 自行再算。
- 没有可靠来源拆分的字段，允许只给 `total`，不可伪造拆分。
- `battle=null` 输出局外配装总值；有 battle 时可反映战斗实时状态。
- 数值需有限、非 NaN；百分比使用现有项目统一口径。

**验收样例**：裸体英雄、装备属性、同组唯一效果、卡牌和羁绊、战斗中的护盾/临时攻速不篡改局外快照。

## X03：商店陈旧报价恢复

**负责范围**：经济/仓库业务层和单测；不改 `SupplyShopSheet.kt`。

**目标接口**：购买返回可供 UI 重新读取的最新 state，或提供明确的 `STALE_QUOTE` 失败类型与刷新后的 shelf revision。

**规则**：

- 自动刷新跨周期后，旧 revision 购买不得扣钱或扣库存。
- 失败结果必须携带可立即显示的新库存、价格和倒计时所需状态，避免用户重复点击无反馈。
- 付费刷新不推迟原本自动刷新周期。

**验收样例**：旧报价拒绝且余额不变、刷新后新报价可买、同时请求只有一个成功、售罄项目不可恢复库存。

## X04：合成材料可用性分层

**负责范围**：`CraftingPresentation` 或同包只读模型和单测；不改 `CraftingSheet.kt`。

**输出**：每个配方材料同时给出 `totalOwned`、`lockedOwned`、`consumableOwned`、`missing`。

**规则**：

- 绑定不必然不可合成，锁定才不可消耗；沿用现有配方实际选择规则。
- 可合成判断只能由 `consumableOwned` 决定。
- 既有锁定物料时，模型须明确“持有但已锁定”，不让 UI 写猜测。

**验收样例**：仅锁定材料、锁定加可用、绑定材料、重复配方材料、材料跨仓库位置。

## X05：掉落与事件内容表

**负责范围**：敌人掉落、事件掉落、战斗金币与入场可带金币的数据配置/规则；不改 UI。

**规则**：

- 战后掉落已替代旧的回血/金币/物品三选一。
- 掉落可以包含金币、任意品质和类型物品；事件掉落可更多，但仍走地面拾取和鉴定。
- 第五战目标箱保持直接入库且不受背包容量限制。
- 事件进入需要本局金币，入场可携带金币；需保持死亡和撤离规则。

**交付说明**：附一张掉落表，至少列敌人档位、物品池、金币范围、鉴定需求、事件产出与目标箱例外。

## X06：外部验收与平衡样本

**负责范围**：不改生产代码，运行测试并回传证据。

- 0.1.4 UI 设备验收：320dp、常规手机、字体1.3；远征、整备、掉落、拖拽、旋转、一键拾取、返回远征。
- 常规控制链：眩晕、沉默、缴械、弱/强驱散、BKB、状态抗性。
- 经济样本：新档启动金币、低/中/高档宝箱票价与平均掉落价值、破产救济、商店回收价。
- 每次验收写明 APK 名、随机索引、存档类型、步骤、截图/日志、结果。
