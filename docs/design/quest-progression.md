# Issue #1：任务与副本进度

实现基线：`91cf543`（0.1.6 任务框架与存档 v15）。对应 [issue #1](https://github.com/foxkitsune233/Infinite-Strife/issues/1)。本设计取代旧任务草案中的空内容表；不实施草案中与本 issue 无关的材料兑换和英雄购买渠道替换。

## 规则

- 40 个任务定义，分成 24 个顺序节点：16 个单任务节点、8 个三选一节点。三选一节点的三个任务奖励相同，领取其中一项时永久关闭其他两项。
- 从新系统启用后累计成功行为，可提前积累后续节点的目标，但必须按节点顺序在营地领取。完成节点数按已领取的不同节点计，最大 24；奖励与已领取标志是同一份存档事务。
- 已达成的状态里程碑不因卸装、出售、合成消耗、死亡损失而撤回。旧存档已有背包、安全箱、技能栏、英雄等级、通关次数可直接认可；无法从旧档推断的历史胜场、事件、制作、实际撤离次数不补造。
- 新档仍为 600 金币和原有六名英雄。四位可购买英雄仍可购买；任务重复解锁已拥有英雄时分别补偿 300／500／700／900 金币，不清除已拥有英雄。
- 物品奖励遵守物品目录的绑定属性、每件独立实例 ID 和仓库规则。仓库超出 10000 件、金币溢出、物品定义缺失等失败不扣改任何数据，也不关闭节点。玩家可整理仓库后重试。
- 不新增存档字段，复用 v15 的 `questCounters` / `claimedQuests`；节点归属由稳定任务 ID 及内容表确定。兼容 v1–v14 的原迁移路径及备份、CRC。旧档正在进行的远征保持原箱、战斗和收益规则，仅下一次入场才检查新任务门槛。

## 接入与验收

- `InventoryRules` / `LoadoutRules`：合法移动、换装、配装后观察装备／技能卡／安全箱里程碑。
- `JourneyRules`：入场；首次生成战斗掉落时计胜场；成功事件选择；成功撤离及完整通关；恢复品和保护物品结算保留既有事件接口。
- `NodeLootRules.collect`：单件／批量共用入口，拾取预先携带后放下的物品不计数。当前拾取目标为1且计数封顶；不提供跨放下重拾的通用多次拾取去重。
- `CraftingRules` / `HomeEconomyRules` / `GrowthRules` / `HeroLevelRules`：验证成功后与状态变更一同记录，失败不记数。
- `PlayerRepository.load`：观察可核实的旧档状态里程碑并正常保存，不臆造行为历史。
- UI：整备工具 → 委托任务，按节点顺序显示教学、进度、奖励、前置条件及互斥结果；宝箱详情显示入场锁定原因。

测试覆盖内容数量和奖励引用、节点顺序、互斥与幂等、仓库/溢出失败回滚、旧英雄补偿、真实规则成功/失败计数、难度边界、低难度路径、现有成长认可、重启/备份恢复、v14完整状态与高难战斗迁移。测试结果与运行限制见 `docs/testing/issue-1-cloud-validation.md`。
