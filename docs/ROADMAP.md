# Infinite Strife 路线图

## 目标

在不影响已完成 Android 课程设计交付的前提下，建立原创设定的 Godot 版本，并逐步迁移为主版本。Android 版继续维护，直到 Godot 版达到明确的可替代门槛。

## 产品与平台策略

| 平台 | 当前策略 | 进入条件 |
| --- | --- | --- |
| Android 原版 | 继续维护和发布 0.x 更新 | 已有构建、测试包与现有玩家 |
| Godot Windows | Godot 版首个运行平台 | 用于快速调试战斗、输入与资源 |
| Godot Android | Godot 版第二个目标 | Windows 验收通过后导出真机包 |
| Godot Web | Godot 主版本完成后的可选分发渠道 | 不阻塞 Android 替代；另行完成浏览器兼容性验收 |
| 原生 iOS | 后置，不承诺日期 | 有合规 macOS/Xcode、Apple 开发者账号和真实 iPhone 后启动 |

Godot Web 版不是原生 iOS 的替代品；若后续启用，它只用于低门槛试玩。性能、触摸、后台恢复和商店分发仍须由原生 iOS 版本单独验收。

## 双轨原则

1. Android 现有包继续作为课程设计交付物、问题复现基线和数值参照。
2. Godot 不直接改写 Android 工程；使用独立 `godot/` 目录、独立场景与脚本，避免半迁移状态破坏已可玩的版本。
3. 规则以可读配置和测试用例定义，不以 Android View 细节为唯一真相。
4. Godot 首版只移植“一个完整可玩回合”，不迁移全部仓库、事件与旧 UI。
5. 每一阶段均以可运行产物和验收记录为结束条件，不以“代码写完”为完成标准。

## 原创与训练数据边界

- Godot 版使用原创英雄名称、造型、轮廓、装备名称、卡面、场景和音频。
- 不把 Dota 角色、标志、可识别设定、第三方原画或其重绘衍生物作为公开 Godot 版资源或训练数据。
- 可用于本地模型训练的数据限于项目自制的 GDScript、场景结构、原创资产提示词、原创测试记录和已确认可再利用许可的资源。
- 每个导入资源必须记录来源、许可证、作者、使用范围和替换状态；缺少记录的资源不能进入公开构建。
- Android 旧资源仍遵循 [ART-ASSETS](ART-ASSETS.md) 的隔离约定，不因 Godot 计划而改变其权利状态。

## 阶段与完成门槛

### 阶段 A：Godot 基础验证

- 建立 `godot/` 工程，固定 Godot 版本、渲染模式和导出模板版本。
- 建立原创占位资产包：两名临时英雄、基础攻击、受击、生命条、卡牌图标和战斗背景。
- 在 Windows 跑通固定种子的 1v1 自动战斗；记录每一击、技能和结算结果。
- 输出 Windows 可执行包与 Android Debug 包。

**完成门槛：** 同一个种子重复运行产生相同日志；无资源缺失；可以从主菜单开始一场战斗并看到胜负结算。

### 阶段 B：可玩闭环

- 增加英雄选择、六个装备槽、六张卡槽、卡牌效果、主动技能、60 秒战斗时钟和战斗日志。
- 增加简化的战后掉落与一页背包；第一版使用点击选择与放置，拖放可后置。
- 加入本地存档、版本化存档迁移和“重开/继续”流程。
- 将 Android 版的关键规则用共享测试向量描述：初始属性、伤害、护甲、护盾、控制、技能 CD 与 RNG 种子。

**完成门槛：** 至少一名原创英雄可完成“选择 → 配装 → 战斗 → 拾取 → 保存 → 继续”的闭环，且固定规则向量与预期结果一致。

### 阶段 C：Godot Android 主版本

- 将阶段 B 验收通过的原创战斗、配装、掉落和存档导出 Android 原生包。
- 对触摸、横竖屏、暂停恢复、低内存恢复、存档升级和资源加载执行真实设备验收。
- 逐步迁移 Android 原版的英雄、流派、装备、卡池、宝箱和事件，但每个内容包必须同时具备原创资产和回归记录。

**完成门槛：** Godot Android 版覆盖当前 Android 版的核心闭环，外部设备验收没有阻断性问题，存档安全且可回滚。

### 阶段 D：网页导出（可选）

- 使用 Godot 单线程 Web 导出，部署为静态试玩版。
- 针对触摸屏重做按钮尺寸、缩放、暂停与存档提示。
- 在 Chrome、Edge、Android Chrome 与 iPhone Safari 上测试启动、战斗、保存和恢复。
- 网页版只承诺试玩反馈，不承诺与原生版完全相同的帧率、后台行为或离线能力。

**完成门槛：** 外部玩家可通过链接完成一局；运行异常、浏览器版本和反馈均有记录。

### 阶段 E：内容迁移与替代评估

- 按“英雄 → 流派 → 装备 → 卡池 → 宝箱/事件 → 仓库与合成”的顺序迁移。
- 每次只迁移一个内容包，同时完成原创资产、数据定义、规则测试和设备验收。
- 仅当 Godot Android 版覆盖当前 Android 版的核心闭环、存档安全和主要触摸操作，才讨论停止 Android 原版的大功能更新；网页完成与否不影响此判断。

**替代门槛：** Godot Android 版连续两个测试周期没有阻断性问题；核心流程通过外部验收；不依赖受限美术资源；有可回滚的存档策略。

### 阶段 F：原生 iOS（可选）

只有具备下列条件才启动：合规 macOS/Xcode、真实 iPhone、Apple Developer Program 账号，以及 Godot Android 已完成阶段 C。iOS 首版只做阶段 B 的功能集合，先走 TestFlight，再讨论 App Store 发布。

## Android 维护范围

Godot 阶段 A–D 期间，Android 继续接受：阻断性崩溃修复、战斗规则修复、存档兼容、数值平衡、可读性改进和少量内容补充。避免在 Android 专属 UI 中开展需要长期重构的大型功能，除非它也能转化为 Godot 的规则文档、配置或验收向量。

## 当前下一步

先完成阶段 A 的技术设计：确定 Godot 4 稳定版本、项目目录、原创临时世界观、规则数据边界和首场 1v1 的验收日志格式。此阶段不复制旧 Dota 资源，不把网页试玩作为验收门槛，也不启动原生 iOS 导出。
